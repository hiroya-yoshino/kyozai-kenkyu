# 教材研究Webアプリ 設計書

- 作成日：2026-11-08
- 対象：まず6年理科（啓林館「わくわく理科」令和6年度版）
- 公開URL：https://hiroya-yoshino.github.io/kyozai-kenkyu/

## 1. 目的と成功の条件

**目的**：授業の前に、どの端末からでも単元を開けば、すぐに授業の見通し（時数・各時間の流れ・実験・図）が立つようにする。

**使う人**：最初は作成者（吉野）だけ。のちに校内や校外の先生にも配る可能性がある。

**成功の条件**
- iPad・Windows・Galaxy（スマホ）のブラウザで、3タップ以内に目的の単元ページを開ける
- 6年理科の10単元すべてに、目標・導入・毎時間の流れ（めあて・活動・まとめ）・実験（準備物・手順・安全・図）がそろっている
- 運用費は0円（API料金なし、GitHub Pagesで公開）

## 2. 決まっていること・仮定

| 項目 | 内容 | 種別 |
|---|---|---|
| 公開方法 | GitHub Pages（Publicリポジトリ） | 決定 |
| 作り方 | HTML・CSS・JavaScript（ビルドなし）＋単元ごとのJSON | 決定 |
| 中身 | Claudeが事前に作成し、作成者の確認を経て公開 | 決定 |
| 出力 | アプリ画面上に表示（Word出力はしない） | 決定 |
| 図 | SVGで手作り。文字は実テキストで表示 | 決定 |
| 単元と時数 | 啓林館 年間指導計画 標準案（3学期制）の配当時数 | 決定 |
| ログイン | なし | 決定 |
| 教科書本文 | 載せない。単元名・時数・オリジナルの指導内容のみ | 決定 |
| 児童の情報 | 一切入れない | 決定 |
| 番号のない時間（ガイダンス・自由研究・みんなで使う理科室・これまでの学習をつなげよう） | 一覧に表示のみ、単元ページは作らない | 仮定 |
| 5年タブ、算数・国語 | 「準備中」と表示 | 仮定 |

## 3. 画面構成

```
① ホーム：教科カード（理科／算数＝準備中／国語＝準備中）
② 単元一覧：学年タブ（5年＝準備中｜6年）
   学期ごとに区切り、各行に「番号・単元名・時数・実施月」
③ 単元ページ
   ├ 上部：単元名・時数・実施月、［🎯 目標］ボタン、目次（導入／第1時〜）
   ├ 導入のアイデア
   └ 毎時間の流れ（第○時を押すと開閉）
       めあて／活動／まとめ
       実験がある時間：準備物・手順・安全上の注意・図
```

### 目標の表示（ポップアップ）
- ［🎯 目標］ボタンを押すと、ページ遷移せずに重ねて表示する
- ×ボタン、外側のタップ、Escキーで閉じ、元のスクロール位置のまま単元ページに戻る
- 中身は3観点（知識・技能／思考・判断・表現／主体的に学習に取り組む態度）

### 端末ごとの表示
- 幅 768px 未満（スマホ）：1列
- 幅 768px 以上（iPad・PC）：左に単元一覧、右に単元ページの2列

### 画面の移動
- URLのハッシュで状態を表す（例：`#/rika/6/01`）。ブラウザの「戻る」がそのまま使え、単元ページのURLを共有できる

## 5. ファイル構成

```
index.html            画面の入口
css/style.css         見た目
js/app.js             画面の切り替え（ハッシュルーティング）
js/render.js          データから画面を組み立てる
js/modal.js           目標ポップアップ
data/index.json       教科・学年・単元の一覧（準備中フラグを含む）
data/rika/6/01.json   単元ごとのデータ（01〜10）
figures/rika/6/*.svg  図
tests/                自動チェック
docs/specs/           設計書
```

各ファイルの役割は1つに絞る。画面のコードは単元の中身を知らず、データの形だけに依存する。

## 6. 単元データの形

```json
{
  "id": "01",
  "title": "ものが燃えるしくみ",
  "hours": 8,
  "month": "4月",
  "term": 1,
  "goals": {
    "knowledge": "…",
    "thinking": "…",
    "attitude": "…"
  },
  "intro": { "question": "…", "presentation": "…" },
  "lessons": [
    { "n": 1, "aim": "…", "activities": ["…"], "summary": "…" },
    { "n": 2, "aim": "…", "activities": ["…"], "summary": "…",
      "experiment": {
        "materials": ["…"],
        "steps": ["…"],
        "safety": ["…"],
        "figure": { "src": "figures/rika/6/01-2.svg", "caption": "…" }
      } }
  ]
}
```

任意の項目：各時間の `stage`（次）と `evaluation`（評価規準）、単元の `sources`（参考資料：title・url・note）。画面では、次・評価・参考資料として表示する。

ルール
- `lessons` の数は `hours` と一致する
- `goals` は3観点すべてそろえる
- `experiment.figure.src` のファイルは必ず存在する
- 実験がある時間は `safety` を1つ以上書く

## 7. 図の作り方

- SVGで1枚ずつ手作りする（例：集気びんとろうそく、実験用てこ、月と太陽の位置関係、地層）
- 図の中の文字はSVGの `<text>` で書き、画像に埋め込まない
- 色数は少なめにし、白黒でも区別できるよう線の種類や模様も使う
- 作成後、ブラウザで表示してラベルのずれや文字の重なりがないか1枚ずつ確認する

## 8. 中身の作成と品質確認

1. 教科書会社の年間指導計画と、単元ごとの指導計画・評価規準の資料（NotebookLM で収集。手順は `docs/notebooklm.md`）の時間配分に合わせて、Claudeが下書きする（2026-11-08 追記。詳しいルールは `CLAUDE.md`）
2. 学習指導要領 理科編（文部科学省）と照らし合わせ、目標のずれを確認する
3. 加熱・薬品・火を扱う時間は、安全上の注意を特にていねいに書く
4. 1単元ずつ作成者が確認し、OKが出たものから公開する

## 9. エラー時の表示

- 単元データが読み込めない：「この単元はまだ準備中です」と表示し、一覧に戻るボタンを出す
- 図が読み込めない：図の位置に説明文（caption）だけを表示する
- 存在しないURL：ホームに戻す

## 10. テスト

- **データの自動チェック**（Node.jsのスクリプト）：全単元について、6章のルールを満たすか確かめる
- **画面の自動チェック**（Playwright）：単元を押すと単元ページが開く／目標ポップアップが開閉する／スマホ幅で1列、iPad幅で2列になる
- **見た目の確認**：Claude in Chromeで、スマホ・iPad・PCの3つの画面幅で表示して確かめる

## 11. 公開の流れ

1. Claudeが変更を `main` ブランチに保存する
2. GitHub Pagesが自動で更新する（1〜2分）
3. 同じURLで最新版が見られる

## 12. あとから追加する機能（今回は作らない）

**自分専用の生成モード**
- 設定画面でAnthropic APIキーを入力すると、その端末のブラウザ内（localStorage）にだけ保存する
- キーがある端末にだけ「AIで作る」ボタンを表示する。生成結果は6章と同じ形で表示する
- 「データとして保存」でJSONファイルをダウンロードし、正式な単元として追加できる
- Anthropicの管理画面で、月の使用上限を設定しておく

**ほかの教科・学年への拡大**：`data/index.json` に追加し、単元JSONと図を足すだけで対応できる。
